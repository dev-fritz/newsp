# Contributing to newsp

Thanks for helping. newsp is a self-hosted, multi-user market radar: it collects news, writes a
daily report per user and generates project ideas that never repeat. Bug reports, documentation
fixes, new connectors and small improvements are all welcome.

By participating you agree to the [Code of Conduct](CODE_OF_CONDUCT.md). For security problems,
follow [SECURITY.md](SECURITY.md) instead of opening an issue.

## Before you start

- Look for an existing [issue](https://github.com/dev-fritz/newsp/issues) first. For anything bigger
  than a small fix, open an issue (or comment on one) so the approach is agreed before you code.
- Read [How it works](docs/how-it-works.md) and [Architecture](docs/architecture.md) for the
  pipeline, data model and main decisions.
- Read the `AGENTS.md` of the folder you touch. They are the engineering rules for humans and
  coding agents alike.

## Repository layout

```text
api/            Go backend: HTTP API, worker, migrations, tests   (rules: api/AGENTS.md)
web/            React Router app and its BFF                      (rules: web/AGENTS.md)
docs/           MkDocs documentation site
scripts/        Helper scripts (init-env.sh)
.github/        Issue forms, PR template, Dependabot, CI, CodeQL, docs deploy
docker-compose.yml   Full stack (db, migrate, api, worker, web) and dev database
AGENTS.md       Repository-wide rules
```

## Development setup

The [development guide](https://dev-fritz.github.io/newsp/development/) has the details. In short:

```bash
# Backend (Go 1.27, Docker for Postgres)
cd api
cp .env.example .env
make infra-up migrate run     # API on :8080
make worker                   # in another terminal: collection and generation jobs

# Frontend (Node 24+, pnpm)
cd ../web
cp .env.example .env
pnpm install
pnpm dev                      # http://localhost:5173
```

To run the full stack in containers, see the
[installation guide](https://dev-fritz.github.io/newsp/installation/).

## Rules that matter

The complete contract is in [`AGENTS.md`](AGENTS.md), [`api/AGENTS.md`](api/AGENTS.md) and
[`web/AGENTS.md`](web/AGENTS.md). The short version:

- **Measure, do not assert.** No claimed quality, cost or performance gain without a test or a
  reproducible number.
- **Never commit secrets** (`.env`, API keys, tokens) or raw third-party content. Test fixtures
  are short and synthetic.
- **Ideas never duplicate.** Changes to idea generation must keep the dedup path (embedding
  similarity, then LLM judge, then merge into a new version) and its tests green.
- **AI providers stay swappable.** Services reach models through `AIGateway` and small ports
  (`Embedder`, `GenerationAI`); providers implement `ai.Provider`. Never depend on a vendor API
  shape. Local models must keep working.
- **Keep `/api/v1` compatible** unless the change explicitly authorizes a break. Regenerate the
  Swagger spec and `web/src/types/api.ts` when the contract changes.
- **Backend:** hand-written SQL (no ORM), layered handlers, services and repositories, tests next
  to the code. **Frontend:** the browser only talks to the BFF; tokens never reach client code.
- Focused diffs, tests with the code, no opportunistic refactors.
- Do not edit `CHANGELOG.md` by hand.

## Checks to run before opening a PR

Run the ones for the folders you changed, from the repository root. CI runs the same gates.

```bash
# api/
(cd api && make check)        # go vet, golangci-lint, go test -race, build, gofmt

# web/
(cd web && pnpm lint && pnpm typecheck && pnpm format:check && pnpm build)

# docs/ (needs: pip install -r docs/requirements.txt)
mkdocs build --strict
```

Backend integration tests use testcontainers and need Docker. `make test-short` skips them for a
quick loop. `make tools` installs the pinned `golangci-lint`.

## Commits and pull requests

- **Conventional Commits 1.0.0** for every commit message and for the PR title, for example
  `feat(api): add youtube channel validation` or `fix(web): keep the draft when the job fails`.
  Allowed types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`,
  `chore`, `revert`. Mark breaking changes with `!` and a `BREAKING CHANGE:` footer.
- The PR title is checked by CI because PRs are squash-merged and the title becomes the commit.
- Reference the issue in the footer (`Refs: #123`) and describe how you verified the change.
- Keep PRs small and focused. Fill in the PR template.

## Changelog

`CHANGELOG.md` is generated by [git-cliff](https://git-cliff.org) from Conventional Commits using
[`cliff.toml`](cliff.toml). Maintainers regenerate it at release time:

```bash
git cliff --unreleased --tag vX.Y.Z --prepend CHANGELOG.md
```

Do not edit it by hand. A clear commit message is your changelog entry.

## Documentation

The docs site lives in [`docs/`](docs/) and is built with MkDocs Material. Preview it with:

```bash
pip install -r docs/requirements.txt
mkdocs serve
```

PRs that touch `docs/` or `mkdocs.yml` are built with `--strict`, so broken links fail the check.
User-facing behavior changes should update the matching page.
